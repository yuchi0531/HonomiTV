# HonomiTV — Fork の変更点

本リポジトリは [makeding/HonomiTV](https://github.com/makeding/HonomiTV) の Fork です。
upstream の `recording-chase-playback` ブランチ（`04090092`）を基点に、独自の機能追加と修正を行っています。

KonomiTV 本体の概要・セットアップ・設定方法は upstream の README を参照してください。
ここでは **本 Fork で加えた変更** だけをまとめます。

---

## 追加した機能

### キャプチャギャラリー

視聴中に保存したキャプチャ画像を、一覧で管理できるようにしました。

- グリッド表示のギャラリー画面（`/captures`）
- 仮想フォルダによる分類・並べ替え
- ライトボックス表示
- 削除は管理者のみ（誤操作を防ぐため）

キャプチャの保存形式は 16:9 に補正します。1440×1080 + SAR 4:3 で配信される映像は、
`createImageBitmap()` が SAR を適用しない場合に横へ潰れた画像になるため、
縦解像度を保ったまま横を 16:9 へ引き伸ばして保存します。

### Annict 連携

Bangumi 連携に加えて、[Annict](https://annict.com/) との連携を実装しました。両者は独立して併用できます。

- 個人用アクセストークンによるアカウント連携（トークンは暗号化して保存）
- 視聴完了時の視聴記録 (record) の自動投稿（既定はオフ）
- 作品照合はマイリスト（見てる／見た）を優先し、無い場合はタイトル検索で補完
- 手動紐付け（未紐付けのシリーズ一覧から、Annict 作品を検索して指定）
- 設定画面（`/settings/annict`）

作品照合は Bangumi と共通の `SeriesMatcher` を使います。タイトルの正規化・話数の抽出・
続編表記の扱いを一手に引き受け、両サービスで同じ判定基準になります。

視聴完了の判定は **ファイル全体の 90%** に統一しました。以前は CM 区間が検出されていると
「最後の CM 群の 3 分前」を完了位置にしていましたが、前後の CM をカットした録画では
CM が検出されず判定が安定しないため廃止しています。

### 録画通知の拡張

通知できるイベントを整理し、Amatsukaze 連携を追加しました。

| イベント | 発生条件 |
| --- | --- |
| `RecordingStarted` | 録画中と判定された最初の 1 回 |
| `RecordingCompleted` | 録画バックエンドが「録画中」→「録画完了」へ遷移させたとき |
| `FileDetected` | ファイル監視が新たにファイルを見つけたとき |
| `FileDeleted` | 録画ファイルが削除されたとき |
| `EncodeCompleted` | Amatsukaze のエンコードが完了（失敗も含む） |
| `ReservationAdded` / `ReservationDeleted` | 録画予約の追加・削除 |

- イベントは通知先ごとに `events` で選択できます（省略時は `RecordingCompleted` のみ）
- `RecordingCompleted` と `FileDetected` を分けたことで、「録画が終わった」と「ファイルが増えた」を別々に選べます
- Amatsukaze は `/api/queue` を定期的に確認して検出します。起動直後の初回取得では既存の完了済みを通知しません
- 録画完了通知には EDCB が記録したドロップ／スクランブル数を含めます（FFprobe では取得できない情報です）

通知の送信失敗は録画や予約の処理を止めません。予約は既にバックエンド側で成功しているためです。

### BS4K のパススルー方式

BS4K ライブ視聴の再生方式を設定で選べるようにしました。

- `TLV`: Raw MMTS をそのまま再生（通常の BS4K 環境）
- `MPEG-TS (HEVC)`: dantto4k などで H.265 の MPEG-TS へ変換している構成

後者の構成では Mirakurun が `decode=0` でも MPEG-TS を返すため、TLV として解釈できません。
サーバー側では `copy` 品質として、`tsreadex` を通したうえで再エンコードせずに配信します。

### グリッド表示

録画番組一覧をリスト／グリッドで切り替えられるようにしました。

- 一覧画面（`/videos/programs`）、マイリスト、視聴履歴、ビデオホームの各セクション
- 画面幅に応じて列数が変わる（`auto-fit` と `minmax`）
- 表示状態は端末ごとに保存

## 追加した設定

| 設定キー | 既定 | 内容 |
| --- | --- | --- |
| `show_partially_recorded_badge` | 有効 | 「一部のみ録画」バッジを表示するか |
| `tv_hide_pinned_tab_when_empty` | 有効 | ピン留めが 0 件のときピン留めタブを隠すか |
| `video_list_grid_view` | 無効 | 録画一覧をグリッドで開くか |
| `navigation_visible_items` | 全項目 | PC のサイドバーに表示する項目 |
| `bs4k_live_passthrough_mode` | `TLV` | BS4K のパススルー方式 |
| `notifications.amatsukaze` | 無効 | Amatsukaze 連携（URL・確認間隔） |

「一部のみ録画」バッジは、前後の CM をカットする運用では全番組が放送時間より短くなり
常時表示されるため、オフにできるようにしています。

## 修正した不具合

### 録画検出と通知

- **EDCB / EPGStation 構成で録画フォルダの監視が動いていなかった** — `start()` を Mirakurun 構成でしか呼んでいませんでした。バックエンドの種類に関わらず一括スキャンと変更監視を開始するようにしました。
- **録画完了通知が遅かった** — サムネイル生成と CM 解析の両方が終わるまで通知を待っていました。サムネイル生成直後に送るようにし、CM 解析の完了は待たないようにしました。
- **確認間隔が過剰だった** — 録画完了の確認を 5 秒間隔で行っていましたが、番組は分単位で編成されるため 1 分間隔に変更しました。
- **サムネイルが失われることがあった** — DB に情報があるのに実ファイルが無い状態を、起動時に検出して再生成するようにしました。
- **`field_order` が `unknown` の録画が再エンコードされていた** — HEVC など VUI にフィールド情報が無い映像で ffprobe が `unknown` を返すと、インターレース扱いになってパススルー対象外になっていました。実フレームの `interlaced_frame` から判定するようにしました。

### 録画予約

- **録画後の bat ファイルが実行されなかった** — 予約作成時に `bat_file_path` を空文字で送っていたため、EDCB の `[REC_DEF] BatFilePath` 設定が上書きされていました。明示指定が無い場合は EDCB の既定値を使うようにしました（キーワード自動予約も同様）。

### シリーズ・番組表

- **シリーズ詳細 API が全件 500 エラー** — `broadcast_periods` は 1 対多の逆参照ですが `select_related` を使っていたため、`list` を要求するスキーマと一致しませんでした。
- **シリーズ詳細でチャンネルが解決されなかった** — `channel` と `recorded_video` は `select_related` で取得するよう修正しました。

### 表示

- **録画一覧の放送時刻・番組長がファイル基準だった** — 録画マージンや CM カットで実際の放送とずれるため、EPG の値を使うようにしました。サムネイル上の時間だけは、実際に再生されるファイルの長さを示します。
- **ホームを開くと BS タブが開いた** — タブのインデックスを `1` に固定していたため、ピン留めタブの有無で別のタブが開いていました。タブ名から位置を引くようにしました。
- **スマホでタブのインジケーターがずれた** — ハイライトをコンテナ幅から計算していましたが、タブは固定幅で横スクロールするため、実測値を使うようにしました。
- **IPTV 未設定でも「ネット」タブが出た** — 未設定時は空タブを削除するようにしました。

## 開発について

upstream の構成・コーディング規約に従っています。

- `server/`: Python / FastAPI / Tortoise ORM（`uv run` 経由で実行）
- `client/`: Vue 3 / TypeScript / Vuetify（`client/` で `yarn` を実行）

コード変更後は以下を実行してください。

```bash
# サーバー
cd server
uv run task lint

# クライアント
cd client
yarn lint
yarn typecheck
```

テストは `uv run python -m unittest discover -s tests`（サーバー）と `yarn test`（クライアント）で実行できます。
