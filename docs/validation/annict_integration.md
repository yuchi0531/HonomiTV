# Annict 連携

## 契約

- `POST /api/annict/auth` で個人用アクセストークンを受け取り、`GET /v1/me` で有効性とプロフィールを確認してから保存する。トークンは既存の Fernet 鍵で暗号化し、クライアントへは返さない。Bangumi と同じく、外部 API の検証がすべて終わってから DB を更新する。
- 認証エラーは 422 (`Annict access token is invalid`)、Annict 側の障害は 502、接続不能は 503 として区別する。401 を「トークンが無効」以外の意味に使わない。
- アクセストークンはクエリ文字列ではなく `Authorization: Bearer` ヘッダーで送る。Annict はクエリでの受け渡しも許すが、アクセスログやブラウザ履歴に残るため使わない。
- `DELETE /api/annict/logout` は公開プロフィールとトークンをまとめて消去し、部分的な連携状態を残さない。
- Bangumi と Annict は同じユーザーが同時に連携できる。`User` に `annict_*` カラム群を別途持たせ、`Series` は `bangumi_subject_id` と `annict_work_id` を同時に保持できる。`annict_work_id` には Series 単位の一意制約を課す。
- 作品照合は `SeriesMatcher` に共通化した。表記揺れ (NFKC・空白・リマスター表記・末尾句点) の吸収、副題境界の判定、続編表記 (期・劇場版・OVA など) の除外、曖昧な候補を自動確定しない閾値は Bangumi と完全に共通で、`BangumiClient` の既存テスト 29 件が同じ結果を返すことを確認している。
- Annict の `sort_number` は 10 倍された通算話数なので、10 で割って EPG 話数と照合する。10 の倍数でない値 (特別編など) は話数として扱わない。同じ話数が複数ある場合は誤って選ばない。
- 視聴記録は `POST /v1/me/records?episode_id=N` で作成する。Annict にはエピソード単位の「看過」フラグが無く、record の作成が視聴記録になるため、投稿済みのエピソードを `annict_episode_records` に記録して二重投稿を防ぐ。外部投稿に成功した後に台帳を作り、失敗を成功として扱わない。
- **自動記録は既定で無効** (`annict_auto_record_playback: false`)。Annict の record は公開の視聴ログであり、Bangumi の非公開コレクションとは性質が異なるため、ユーザーが明示的に有効化したときだけ投稿する。オフの間は書き込み API を一切呼ばない。
- 連続放送 (1 本の録画に複数話が入る `5-6` 形式) は対象外とする。1 本の録画から複数話を切り出す必要があり、誤った話へ公開記録を残すリスクの方が大きいため。
- Annict のトークンは自動更新されない (Bangumi の 30 日トークン後継発行 API に相当するものが無い)。保存と検証だけを行い、失効時は再連携を促す。書き込みには「読み込み + 書き込み」スコープが必要で、403 は再連携・スコープ変更を促すメッセージへ変換する。
- 作品一覧の同期は Bangumi と同じ 30 分間隔の定期タスクで行い、連携直後は API レスポンスと切り離してバックグラウンドで開始する。1 件の失敗が他の作品の照合を止めない。
- Annict には Bangumi の「条目統合」に相当する仕組みが無いため、同じ作品に複数の Series が紐付きそうな場合は警告ログを残して片方をスキップし、Series 同士の自動統合は行わない。

## 検証

- `server/tests/test_annict_client.py` (25 件): 話数正規化 (10 倍値・非倍数・不正値)、エピソードの一意照合、作品照合 (完全一致・英語表記・曖昧候補の拒否・無関係タイトルの拒否)、Bearer ヘッダーの使用とトークンの URL 非搭載、ページネーション (`next_page` 追従・空ページでの打ち切り)、ステータス横断の候補統合、record 作成の応答検証、403 の伝播、自動記録の既定オフ、`SeriesMatcher` と `BangumiClient` の結果一致、Series の両 ID 同時保持・一意制約・エピソード記録の一意制約。
- `server/tests/test_annict_playback_sync.py` (7 件): 実メモリ内 SQLite を使い、完了時の record 作成、二重投稿の抑止 (`AlreadyCompleted`)、未完了での不投稿、未照合 Series の対象外、話数不一致での不投稿、範囲録画の不投稿、未連携ユーザーと存在しない録画のエラーを検証する。
- 実 API に対して、無認証・不正トークンの `GET /v1/me` がどちらも 401 を返すこと、`/v1/works` と `/v1/me/works` が認証必須であることを確認した。ルーターの 401 処理と、常に認証ヘッダーを付ける設計がこれに一致する。
- マイグレーション `19_20261018010000_update.py` を既存 19 個の後続として適用し、`users.annict_*` / `series.annict_*` / `annict_episode_records` と各インデックスが作成されること、ORM から読み書きできることを確認した。
- クライアントの ESLint / TypeScript / 全 122 テストと本番ビルドが通る。
- 実際の Annict アカウントでの連携と record 投稿は、個人用アクセストークンが必要なため未検証。ユーザー管理のサーバーを無断で起動・再起動しない。
