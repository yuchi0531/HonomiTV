# キャプチャギャラリー

## 契約

- サーバーの `capture.upload_folders` に保存された JPEG / PNG を、クライアントの `/captures/` から一覧・検索・拡大表示・削除できる。キャプチャ画像は DB にレコードを持たないため、常にファイルシステムが正であり、実ファイルが消えたものは一覧から自動的に外れる。
- 一覧は `os.scandir()` で保存先フォルダ直下のみを走査する (サブフォルダは対象外)。同じファイル名が複数の保存先フォルダにある場合は、設定順で先のフォルダを正とする。並び順はファイルの更新日時。
- 1 ページ 36 件。36 はグリッドの列数 (デスクトップ 4 / スマホ横 3 / スマホ縦 2) の最小公倍数で、最終行だけ極端に列数が少なくなることを避ける。
- EXIF の `XPComment` (タグ `0x9C9C`) にクライアントが UTF-16-LE で書き込んだ JSON を番組メタデータとして読む。Pillow の `getexif()` はヘッダーのみを読むため、全件走査しても画素のデコードは発生しない。EXIF が無い・壊れている・未知の形式のキャプチャでも一覧からは消さず、`capture_metadata` を `null` として返す。
- `capture_metadata` の `network_id` / `service_id` / `event_id` は `null` を取り得る。ネットテレビ (Jellyfin) 由来のチャンネルや、放送波の識別子を持たない録画ではこれらが埋まらないため、サーバー側スキーマも nullable にしてある。
- 検索はファイル名・番組名・チャンネル名の部分一致。EXIF にチャンネル名は入っていないため、チャンネル名検索は `Channel` テーブルから解決した `(network_id, service_id)` との照合で実現する。
- 画像取得 API は原寸とサムネイル (`?thumbnail=true`、長辺 400px の JPEG) を返す。ETag はファイルの (名前, 更新時刻, サイズ, サムネイル可否) から生成し、`If-None-Match` 一致時は本文なしの 304 を返す。サムネイルと原寸で ETag は別物になる。
- ファイル名の解決は拡張子のホワイトリスト (`.jpg` / `.jpeg` / `.png`) と、解決後のパスが保存先フォルダ配下であることの両方を必須とする。`..` やディレクトリ区切りを含む名前は、`resolve()` に到達する前に拒否する。
- キャプチャの削除は管理者 (`GetCurrentAdminUser`) のみ可能。録画ファイル削除 API と同じ権限モデルに揃えている。削除時は実ファイルを消したうえで、全ユーザーのフォルダから同じファイル名のブックマークも掃除する。
- 仮想フォルダは `capture_folders` (ユーザーごと) と `capture_bookmarks` (フォルダとファイル名の紐付け) で表現する。実ファイルの移動・コピーは一切行わない。1 つのキャプチャを複数のフォルダに登録できる。
- フォルダ操作 (一覧・作成・改名・削除・追加・解除) はログイン必須。他ユーザーのフォルダは存在自体を伏せるため 403 ではなく 404 を返す。フォルダ削除でブックマークは CASCADE 削除されるが、キャプチャ画像は残る。
- フォルダへの追加時は、リクエスト内の重複と既登録分を除き、実ファイルが存在するものだけを登録する。実ファイルが無いブックマークは幽霊レコードになるため作らない。フォルダ一覧の `capture_count` は登録件数 (実ファイルが消えたものを含む) であり、フォルダ内一覧の `total` は実在するものだけを数える。
- フォルダ名は前後の空白を除去し、空文字と 100 文字超を 422 で拒否する。
- 同期ファイル I/O は `asyncio.to_thread()` に逃がすか、API ルート自体を同期関数 (`def`) にしてスレッドプールで実行する。イベントループをブロックしない。
- 画像取得 API は認証を要求しない。`<img src>` から直接読むため Bearer ヘッダーを付けられず、KonomiTV は家庭内 LAN での利用を前提としている。キャッシュは `Cache-Control: private` とし、共有キャッシュには残さない。

## 検証

- サーバー: 実 SQLite (メモリ内) と実ファイルを使い、並び順・ページネーション・EXIF の読み取り (正常/欠落/破損)・ファイル名/番組名/チャンネル名検索・原寸とサムネイルの配信・ETag による 304・トラバーサル拒否・管理者のみの削除とブックマーク掃除・フォルダ CRUD と所有者境界・実ファイルが消えたブックマークの除外・アップロードの JPEG 受理と非画像拒否を検証する。
- クライアント: ESLint / TypeScript / コンポーネントテストで、空状態、選択モードの上限 4 件、選択解除での選択モード終了、右クリックでの選択モード開始、管理者判定、未ログイン時のフォルダ非表示、検索結果表示、API クライアントの URL エスケープと 401 の無通知を検証する。
- DB マイグレーションは既存の 18 個の後続として適用できること、`capture_bookmarks` のユニーク制約と `capture_folders` 削除時の CASCADE が実スキーマで機能することを確認する。
- 実ブラウザでの操作 (ライトボックス、長押し、実キャプチャ画像での見た目) は、ユーザー管理のサーバー API と保存済みキャプチャがある環境でのみ確認できる。起動中のサーバーを無断で再起動しない。
